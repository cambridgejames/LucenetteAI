# 模块文档模板

> 用途：docs/02-modules/ 下的所有模块规格必须按本模板组织。一份模块文档 = 一个可独立发包的工作单元。本模板同时是文档作者的自检清单与发包方的验收清单。

## 模板

```markdown
# <模块名>（<编号>）

## 1. 概述
- 定位：本模块在六大系统中的位置
- 职责边界：In scope（做什么）/ Out of scope（不做什么）

## 2. 依赖与接口
- 依赖：引用的契约文档（docs/01-contracts/）与其他模块
- 对外接口：本模块暴露的接口/协议/事件

## 3. 内部结构
- 架构图（mermaid）
- 组件划分与职责

## 4. 数据模型
- 数据结构/消息体/存储表定义

## 5. 关键流程
- 时序图：正常路径 + 异常路径

## 6. 异常与降级
- 各故障场景下的行为要求（上报/重试/降级/熔断）

## 7. 配置项
- 参数清单：名称/默认值/取值范围/修改方式（管理面可下发?）

## 8. 非功能需求
- 延迟/吞吐/内存/并发等量化指标

## 9. 验收标准
- 可测试的 DoD 清单（逐条勾选）

## 10. 任务书（发包用）
- Background：上下文与目标
- Task：具体任务拆解
- Constraints：约束（契约/规范/技术栈）
- Deliverables：交付物清单
- Test：测试与验收方法
```

## 写作要求

1. 每份文档独立可读：只引用、不复述其他文档内容（复用契约用链接）；
2. 图表必须可渲染（mermaid 语法通过校验）；
3. 量化指标给出具体数值，禁止尽量快、尽可能等模糊表述；
4. 第 10 节按可直接粘贴给 AI 执行的标准撰写；
5. 文档变更在文末追加变更记录（版本/日期/摘要）。
